Features

What AutoSongs does

Four pillars: notice what plays, fetch it through your own bridge, keep it in the format you chose, and stay out of the way afterwards.

Detection Formats Guard rails Metadata & library The bridge Reliability

Detection: it hears every track you play

AutoSongs attaches to Android's media sessions. As soon as a new track starts — in YouTube Music (ReVanced) or any app you allow — it reads the title, artist, album, artwork and playback position, queues a download, and gets back to listening for you.

  • Media-session detection — title, artist, album, artwork, position.
  • Notification fallback — media notifications are parsed too, so nothing slips through.
  • Automatic firing — a download starts on every new track, as you listen.
  • Foreground watcher service — keeps running while you play; exclude it from battery optimisation and it rides through the whole session.

Formats: your library, your rules

AutoSongs hands yt-dlp the right format flags and finishes the job with clean output. One tap in the app changes every future download.

Guard rails that keep the library clean

Before it downloads

  • Minimum track length — skips ads and short clips.
  • Start after N seconds of playback — skips tracks you skip immediately.
  • Artist blocklist — comma-separated names to ignore.

After it downloads

  • Dedupe window — no re-downloading the same track within N hours, so loops stay quiet.
  • Already-have memory — the app remembers what it saved, even across restarts.
  • One library folder — everything lands in Music/AutoSongs/, easy to inspect, move or delete.

Real library files, not a folder of downloads

Every finished file carries title, artist and album tags plus embedded cover art from the source artwork, is written into Music/AutoSongs/, and is indexed in MediaStore — so it shows up in every music app on the device without import rituals.

What that means day to day

  • Offline players, car integrations and file managers all see the same files.
  • Artwork and tags survive, so the library looks like a library.
  • You can delete or move anything by hand — AutoSongs never locks it away.

The bridge: your download engine, your machine

AutoSongs includes a yt-dlp bridge and runs it by default. You can also move that bridge to another device — the app never depends on somebody else's server.

  • Token auth — lock the bridge with --token if it might be reachable beyond your LAN.
  • Firewall-friendly — binds 0.0.0.0 by default so LAN boxes work; restrict as needed.
  • Always current — when YouTube changes, update the engine with pip install -U yt-dlp. No app update required.
  • One-tap health check — Test bridge in the app answers Bridge OK — yt-dlp <version>.

Built in, plus four external options

  • Inside AutoSongs (default) — the downloader is already in the app; nothing else has to be installed.
  • Termux on the same phone — install Python and yt-dlp, run the launcher, use host 127.0.0.1.
  • PC / NAS / VPS on your network — autosongs-bridge.sh on Linux, macOS or Termux; AutoSongsBridgeSetup.exe or autosongs-bridge.cmd on Windows.
  • A spare Android phone — the AutoSongs Bridge app turns an old handset into the download box.
  • Code pairing — launchers print an eight-character code; type it into Settings and the two find each other.

Reliability, honestly

When YouTube changes

Downloading is only as reliable as yt-dlp itself. When YouTube moves, a stale engine throws 403s — update it and you are back. The launchers keep yt-dlp in place for you.

When Android gets aggressive

OEM battery managers love killing background services. Keep AutoSongs off battery optimisation and allow background activity, and the watcher survives the whole listening session.
