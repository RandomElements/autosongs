Install

Install AutoSongs. The bridge is already inside.

The Android app includes its yt-dlp bridge by default. Install the APK, grant media access, and start. The optional guides below cover Termux, desktop, NAS, spare-phone, and manual bridge setups.

Requirements 1 · The app 2 · Optional bridges 3 · Connect Troubleshooting

What you need

An Android phone or tablet

Android 8.0 (API 26) or newer. AutoSongs targets the current SDK and keeps a foreground service while watching.

A music app you allow

Built around YouTube Music (ReVanced); anything that publishes a media session or media notifications works the same way.

Nothing extra by default

The bridge runs inside AutoSongs. Choose a remote option below only to put the downloader on Termux, Windows, Linux, macOS, or a spare Android device; those external options may need Python 3.

1  Install the app

  1. Download AutoSongs-1.4.27.apk to the phone (or copy it over from your computer).
  2. Open the file. Android will ask you to allow installs from your file manager or browser — confirm once, and the install runs.
  3. Done. The app is AutoSongs in your launcher and its built-in bridge is enabled by default. Use the options below only to run the bridge somewhere else.
Sideload note. AutoSongs is distributed as a direct APK, not an app-store listing. Only install it from this site's own downloads/ folder, and keep the file you downloaded — the version number in the filename is the version you are running.

2  Optional: run the bridge somewhere else

The built-in bridge is already enabled. Keep it and skip this step, or choose one external option below and pair it with the app.

Option A — Termux on the same phone no other hardware

Install Termux, then run the one-file launcher inside it:

pkg install python
sh autosongs-bridge.sh

Get autosongs-bridge.sh from the downloads folder and copy it into Termux first. The launcher checks for Python 3, installs yt-dlp if needed, starts the bridge on port 8765 and prints an eight-character code.

In the app's Settings use host 127.0.0.1, port 8765 — the traffic never leaves the phone.

Option B — Windows PC

Two ways, same result:

  • Setup installer — run AutoSongsBridgeSetup.exe and the bridge is installed and started for you.
  • Single-file launcher — double-click autosongs-bridge.cmd (or run it from a prompt). Nothing to install.

Both need Python 3 (the launcher tells you how to get it with winget install Python.Python.3), put the bridge into %USERPROFILE%\.autosongs\, keep yt-dlp current, and print an eight-character pairing code.

Option C — Linux, macOS or a NAS

One file, nothing to install:

sh autosongs-bridge.sh

Download autosongs-bridge.sh, run it, and it checks for Python 3, installs yt-dlp if needed, fetches the bridge into ~/.autosongs/, starts it, and prints the eight-character code. Keep it running in a terminal, tmux or systemd.

Option D — a spare Android phone

Install the companion AutoSongsBridge-1.4.26.apk on any second phone or tablet and it becomes the download box — no PC, no Termux. Open it, keep it on the same network, and type the code it shows into AutoSongs.

Option E — run the bridge yourself

Already have a machine you trust? Download the single-file ytbridge.py bridge and run it directly:

python3 ytbridge.py --host 0.0.0.0 --port 8765 --token "your-secret"

It binds 0.0.0.0 by default so LAN hosts work. If the machine could be reachable from anywhere but your own network, set a token or keep it behind a firewall — the app sends that token with every request.

3  Connect and start

  1. Open AutoSongs and tap Grant notification access — enable AutoSongs in the system list. This is how the app sees the track that is playing.
  2. For the default, leave Bridge inside the app enabled in Settings. For Termux, Windows, Linux, macOS, or a spare phone, turn that switch off and use Pair remote bridge with the eight-character code. You can also enter the LAN host, port 8765, and token manually.
  3. Back on the main screen, pick a Download format and tap Test bridge. You should see Bridge OK — yt-dlp <version>.
  4. Tap Start watching. From now on, every new song you play is downloaded automatically into Music/AutoSongs/.
One battery setting matters. Exclude AutoSongs from battery optimisation and allow background activity, or Android may kill the watcher in the middle of a session.

Troubleshooting

Test bridge fails with a connection error

Check the bridge is actually running, then the host and port in Settings (127.0.0.1 only works for Termux on the phone itself; a PC bridge needs its LAN IP, e.g. 192.168.1.40). Phone and machine must be on the same network, and the machine's firewall must allow port 8765 from the LAN.

Downloads fail with “HTTP Error 403: Forbidden”

A stale yt-dlp after a YouTube change — the usual cause. Update it: pip install -U yt-dlp, or simply re-run the launcher, which keeps the engine current. No app update is needed.

Some tracks never download

Check the guard rails: minimum track length, minimum playback seconds and the artist blocklist all skip tracks on purpose. Widen them, then watch the app's status area to see what it detected.

It stops after a while in the background

Battery optimisation. Exclude AutoSongs from it, allow background activity, and keep the notification access enabled. Aggressive OEM battery managers are the most common culprit.

The same song downloads again after a loop

Increase the dedupe window (“skip re-downloading within N hours”) in Settings.

Is the bridge safe on my network?

By default it listens on all interfaces so LAN boxes work. On anything but a trusted network, set --token (or use the launcher's pairing code) and keep the machine behind your firewall. See the privacy page for what data crosses the wire.
