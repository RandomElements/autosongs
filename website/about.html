About

What you stream, you should be able to keep

AutoSongs is a small Android app with one job: everything you play becomes a properly tagged local file, automatically — in the format you chose, in a folder you can see, on hardware you own.

Why it exists

Streaming is renting. Playlists built over years can vanish with one license lapse, and even offline modes keep the files in a private format you can't actually own or move. AutoSongs closes that gap on-device: it watches what plays and saves it — yours, local, tagged, in the library apps you already use. Its tiny yt-dlp bridge is built in by default, and it can also run wherever you want it to: in Termux, on a box at home, or on a spare handset.

How matching works

YouTube Music's media session exposes the title and artist of the track playing. The bridge hands that pair to yt-dlp as a search query and picks the best match — media sessions usually carry the exact video id, so the search resolves cleanly. The guard rails (minimum length, playback seconds, artist blocklist, dedupe window) decide what gets through, and the finished file is written with tags and artwork into Music/AutoSongs/.

Under the hood

  • Android app in Kotlin — a media-session listener service with notification fallback, an in-process event bus, and a foreground watcher service that applies your rules and saves the result. Requires Android 8.0 or newer.
  • The bridge is plain Python — ytbridge.py is a compact HTTP wrapper around yt-dlp and ffmpeg. It runs wherever Python 3 runs: Termux, a Raspberry Pi in a drawer, a NAS, a VPS, Windows.
  • Bridge app — the same idea as an installable Android app, so an old phone becomes your download box, with eight-character code pairing built in.
  • Launchers — autosongs-bridge.sh and autosongs-bridge.cmd are single files that install and start the bridge, keep yt-dlp current, and print the pairing code.
  • Buildable from source — ./gradlew :app:assembleRelease with JDK 17 and Android SDK 35.

What is new in 1.4.27.

Setup no longer hides behind the phone's own bars. From Android 15 the app is drawn edge to edge, which put the setup's Back / Skip / Next row underneath the three-button navigation bar and the screen title underneath the clock — a tap on “Next” went to the phone's button instead of the app's. The walk-through, the home screen and the settings screen now pad themselves by the status and navigation bar height.

The permissions step starts with the app settings page. On Android 13 and newer an app installed from a file rather than the Play Store has notification access locked until “Allow restricted settings” is turned on, and that switch lives only in the app's own settings page. Sending someone to the notification-access list first left them looking at a greyed-out toggle with nothing to explain it.

And the format you pick is the format you get. The home screen was built before the walk-through drew over it and never re-read the saved answer, so choosing MP3 (or Opus, or anything but M4A) came back as M4A when the walk-through finished. The file was always right; the label was not. It is re-read now, and the setup's own radio list ticks the saved choice instead of always ticking the first.

And from 1.4.24, still here: the first run is a walk-through (where the songs go, what kind of file to save, the permissions Android needs, and a summary, each answer saved as it is given), and the bridge can be reached from another network through a Cloudflare tunnel, so a phone on cellular can reach a bridge on a home computer without opening anything on the home network. Once it is reachable from outside, the bridge's own key is required on every request, including the two pairing answers that are open on a local network.

Supporting AutoSongs

AutoSongs is free, and it stays free — no account, no ads, no telemetry, and nothing sold about you. But it is not free to make: the server that hosts the downloads and the bridge, the release work, and the bug reports all cost time and money.

If it saves you a bit of time, a contribution helps keep it maintained and the hosting paid for. It is entirely optional and buys you nothing extra — the same app either way.

You can also say what is wrong with it — a bug report is worth more than a coffee, and there is an issue tracker for it on the project's source page.
